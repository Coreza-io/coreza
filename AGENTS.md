# Architecture rules

- Treat cluster projection nodes as render-only copies; all workflow mutations must start from canonical editor state to prevent hidden display flags leaking into saved/history state.
- Cluster Execute is an editor-local sequence of normal node actions; only explicit Run All uses batch workflow execution.
- Node identity changes are canonical document transactions that update nodes, edges, cluster membership, references, and runtime keys together; projected React Flow copies are never renamed directly.- Custom edges read only their own endpoints via React Flow `useStore` selectors, and cluster projections pass through `reconcileClusterProjection`; whole-node-array subscriptions make every edge and card re-render on each drag frame.

- Persisted clusters may contain disconnected members; only cluster creation requires connectivity. The editor and server validators must agree.
- Cluster Execute repeats a Loop's body per iteration through normal node actions and writes Loop feedback the same way Run All does.

- Cluster execution visual effects overlay reconciled displayed graph copies only; never persist execution flags or edge styles into canonical state or committed base projections.
- Required-field and runtime action failures share guarded publication to local output, execution store and canonical node data, followed by one explicit store notification; detailed errors belong in Output Data.

- Allocate instance names through `src/domain/nodeNaming.ts` against canonical IDs and explicit names, including hidden members. On collision, numbered names continue an existing unsuffixed family (lows, lows1, lows2); preserve literal custom digits when no family root exists. New nodes use the same ID and displayName; labels fall back to the committed ID, never array order. Preserve optional top-level displayName in saved node JSON. Manual file import alone creates fresh UUID identities with separately allocated public names.
- Resolve dragged sources by current canonical ID, then emit their explicit public name only when it resolves back to that same node in the complete inventory; otherwise use the canonical ID. Import remaps selectors to the newly allocated public names under the same rule while retaining fresh UUID identities. Named references resolve exact IDs before unique aliases; ambiguous aliases produce diagnostics. Simultaneously remap supported selectors only in editable values, using aliases proven by the original complete inventory.

- Cluster hierarchy is stored only as optional `parentClusterId` on cluster metadata. `memberNodeIds` is unique direct ownership; scope, movement, summaries, selection and bounds use the portable backend `clusterHierarchy` resolver via the frontend facade. Never persist effective member arrays or React Flow parent IDs. Maximum depth is two; traversal must reject cycles/missing parents before expanding scopes.
- A single transient focus ID derives the expanded ancestor path. Project each canonical leaf through its first collapsed ancestor, allocate only visible compact cards, and preserve one invisible runtime host per hidden leaf. Ancestor frames and legitimate descendants cannot occlude each other. Only explicit canonical-to-projected edge metadata may authorize execution effects or endpoint remapping.
- Document commands commit complete validated candidates once. Dissolution promotes direct ownership and children; ordinary deletion prunes effective-empty containers bottom-up. Clipboard roots attach to the destination while internal parent links remain intact. Never flatten pasted or malformed hierarchy to make an operation succeed.
- Cluster title/note typing stays in local drafts; blur/Enter commits a validated metadata command with one undo entry and Escape cancels. All structural commands check live execution/drag/loading/session guards, including callbacks created before state changes. Flat writes retain the legacy RPC argument shape until hierarchy protection is ready.
- Parse/recover complete relationship components independent of array order. Preserve raw invalid metadata and original source indexes; block lossy saves pending explicit repair. Parent-only changes belong to canonical serialization, dirty comparison, version/history and run snapshots.
- Hierarchy graph writes declare `cluster_format_version: 2`. The authenticated API advertises depth two only after the deployed database readiness RPC confirms its writer guard. Deploy the migration and backend readers/guards before enabling authoring. Old or alternate writers must refuse replacements of nested documents, including submitted flat/empty metadata; supported empty arrays intentionally dissolve all clusters. Rollback disables authoring while retaining readers and write protection.
- Parent Execute captures one effective leaf scope and runs normal actions under one controller/lock. It never recursively starts child runs. Aggregate counts are unique eligible leaves; Loop repetitions are invocations. Child/ancestor progress is derived from the owning snapshot without replacing independent run records. Navigation during execution changes only display.
- Computed slice bounds and nested bound expressions use the shared bounded parser in typed Edit Fields v2 and generic node references across preview/manual/server paths. Ordinary generic templates retain legacy behavior. Resolve expression identities from the complete canonical inventory and outputs from each action's execution-context snapshot, including existing pins. References never infer Run All edges.
- Native reference drops use live text refs, pointer geometry and tolerant lexical spans. Reject unsafe/no-target placement, preserve half-open active selections, and keep caret/field history transient across canonical document restores. Deploy the computed-slice evaluator before frontend authoring.
- `$vars` is a read-only scalar namespace, separate from Store and `$state`, authored only by successfully executed Persistent typed Edit Fields. Manual/upstream/cluster editor actions share the current workflow session; each accepted Execute All uses a fresh batch scope and restores the manual view on teardown. Scope editor requests by server-derived owner, saved workflow, editor session and mode/batch; keep bounded snapshots and invocation receipts in shared Redis with atomic revision checks, idempotent close markers and a 24-hour execution-only idle TTL. Preview never opens or renews a scope. Server runs, backtests and live activations start empty and commit immutable run-local overlays across bars/events/loops until existing teardown releases them; no SQL snapshot seeding, checkpointing or handoff for new activations. New live variable write-behind admissions are disabled; legacy owned scopes must finish fenced stop/handoff or recovery before replacement. Lost variable-dependent live RAM interrupts that activation and requires a fresh activation. Keep limits, whole-batch validation, sequential Loop semantics and the distributed Parallel Loop restriction. Never persist registries in graph/history/results/pins or perform evaluator I/O. Legacy global export, existing SQL rows/receipts/checkpoints, Store, `$state` and legacy Edit rows retain their own behavior.
