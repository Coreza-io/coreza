# Allow Store during backtest warm-up

## Expected behavior

Add a **Backtest session** scope to the built-in Store Variables node. Store nodes with this scope run during Workflow Replay and can read and update the same keys during the main backtest. Each backtest starts with empty session storage. For `smc-fibonacci`, both branches can write `wick_score`, and the rolling list can append, read and clear `wick_scores`. Configure every reader and writer for those keys with the same scope.

## Implementation

1. **Add the scope to the existing Store node.** In [Store.json](../../src/nodes/Store.json), add an explicit `backtest_session` value. Support the current scalar and list operations, including Set Value, Get Value, Delete Key, bounded append and range. Use manual variable names for this scope and hide the cross-workflow variable selector. Validate the scope and supported operations server-side. Existing Store configurations retain their Local and Global behavior.
2. **Route session-scoped Store operations through the existing storage service.** Pass a trusted backtest-session identity from [BacktestSession](../../coreza-backend/src/backtest/session/BacktestSession.ts) through the dynamic and compiled execution contexts into [DataSourceExecutor](../../coreza-backend/src/nodes/executors/DataSourceExecutor.ts). Reuse the scalar and list handlers in [store.ts](../../coreza-backend/src/services/storage/configs/store.ts) with separate Redis keys scoped to the owning user, workflow and backtest session. Resolve the namespace server-side, including for manual editor Store requests, using the authenticated editor session and the current backtest ID. Validate ownership and workflow before allowing access. Requests for this scope without a matching backtest fail with an actionable error. Both reads and writes stay in the session namespace.
3. **Allow the selected scope during warm-up.** In [WarmupPolicy.ts](../../coreza-backend/src/backtest/warmup/WarmupPolicy.ts), allow only the built-in Store definition with the literal `backtest_session` scope. The executor and storage service enforce the resolved scope and session identity before any Redis operation. Local and Global Store, external RedisStore and other integrations retain their existing warm-up rules. The trading rejection stays in place. The [OnBar warm-up flag](onbar-warmup-status.md) can still gate the trading branch while session-scoped Store builds strategy state.
4. **Tie storage to the session lifecycle.** Share the namespace across warm-up and regular bars, including manual steps and owned batch runs. Give reset a fresh namespace before replay starts again. Use existing session cleanup on completion, cancellation, replacement and initialization failure. Keep manual storage available through the final bar's downstream editor actions. Apply an expiry as a backstop so an interrupted cleanup cannot leave keys indefinitely, including keys written with node TTL set to zero.

Scope is the built-in Store node and backtest session execution. Testing is outside this plan.
