# Frontend optimization implementation — 22 October 2026

This change implements the core frontend changes from the consolidated plan on `dev` (`a12009b2`). It adds no dependency, backend behavior, schema, or wire-format change. The requested delivery explicitly excludes testing. No tests, type check, lint, production build, browser profiling, or heap measurements were run. Source review and `git diff --check` are the only checks performed. No FPS, latency, allocation, or memory improvement is claimed.

## Active paths and owners

- `WorkflowEditor.tsx` owns canonical commands, the active inline React Flow canvas, and accepted run preparation. A run constructs one executor from the current canonical graph after preparation and captures registered normal actions under its session lock. Stop addresses that executor. Saving a new workflow queues acceptance until its new session has loaded; it releases the old lock first.
- `canonicalGraphStore.ts` retains full and legacy semantic publications, including top-level mutation signatures. Additive configuration and topology views share unchanged records. Topology includes identity, definitions, tool/branch roles and endpoints, without result payloads or geometry. `StableNodeContext` provides indexed imperative lookup. Input selection indexes are weakly owned by graph arrays.
- `ExecutionContext` stages writes and dirty node IDs. The existing explicit `notifyUpdate` flushes keyed listeners after publication. Status readers select control flags; open outputs and selected inputs read their node; literal reference consumers subscribe to resolved IDs. Dynamic or unresolved references retain a fallback subscription. Historical consumers never subscribe to the live version channel.
- `NodeWrapper` owns expansion and publishes configuration demand. Hidden runtime hosts retain their normal actions and schema hydration while suspending configuration/chart/panel presentation. Scope changes reset drafts and expansion. The canonical document never stores these presentation flags.
- Cluster frames use React Flow's viewport portal. Pure panning does not write editor viewport state. Projection reconciliation, endpoint edge selectors, drag guards and frame-batched execution visuals retain their existing paths.
- `useNodeCredentials` uses the existing React Query client. Keys contain owner, service, endpoint, actual parent value and workflow/session dependencies used by the request. Tokens are read at request time and excluded from keys and cached credential metadata. Static options are derived directly. Configuration demand gates requests; explicit credential changes invalidate owner metadata. Metadata is stale after 30 seconds and collected after five unused minutes.
- Generic preview content mounts on interaction and debounces typing by 250 ms. Hidden fields do not activate variable queries. Configuration preview contexts are reused by canonical snapshot/runtime version. Typed and generic evaluators keep their existing expression semantics.
- Output display derives from authoritative runtime/props and canonical pin state. Accepted local result publication remains available. Pin synchronization uses canonical commands instead of mutating incoming props. An active edit draft survives streaming updates; session/node changes reset it. Historical results do not fall back to saved pins.
- `useExecutionHistory` owns workflow/owner/filter scoped summary queries and selected detail. List rows omit results and graph bodies. Pagination uses `(started_at, id)` keyset cursors independent of retained row count. Completed detail does not refetch on ordinary polling; selection, explicit refresh, relevant realtime invalidation and running status can fetch detail. Realtime payloads retain only summary fields. Detail replacement is isolated and atomic before paint.
- `useScopedLoader` coalesces supporting-page reloads into one current load plus a trailing reconciliation. Live session generations and owner/workflow scope reject old responses. Project counts use the existing relational count query.
- Routes use module-level lazy imports and local loading/error boundaries. Execution transport payload diagnostics require both development mode and `VITE_DEBUG_EXECUTION=true`. Command-only toast consumers use the imperative command.

The unused `WorkflowCanvas`, `WorkflowHeader`, `useWorkflowExecution`, and `NodeExecutionInspector` implementations were removed after checking source, scripts and tests for references. Their removal is source consolidation, not a measured runtime improvement.

## Retention and display policies

- Document undo retains at most 50 past command entries. Document snapshots omit runtime inputs/outputs/progress while retaining editable values, pins, identity and hierarchy. Position deltas remain separate entries. Undo and clipboard clear on session replacement. Clipboard alias inventories contain identity/definition metadata instead of all workflow results.
- Session disposal drops registered pins and runtime data; Clear Runtime retains pins. Deleted identities retire runtime keys. Old execution locks/actions are invalidated before session disposal.
- History retains at most three full details. Summary pagination retains a 200-row window; its cursor is independent of eviction. Hidden history pauses network activity while retaining the current selection/cache in the same data scope. Reopening refreshes the selected detail; explicit list refresh resets pagination to the newest page. When the 200-row limit is reached, pagination and realtime merges retain the older window at the cursor boundary; refresh returns to the newest rows. Owner/workflow/filter changes clear the scope.
- JSON trees lazily expand and page objects/arrays, with a shared 200-entry, 12-level, 20,000-character display budget. Strings display at most 2,000 characters per entry. Source data and reference paths remain unchanged. Output export deliberately serializes the complete value; object URLs are revoked. Edit eligibility is checked through bounded traversal before serialization.
- Chart series retain compatible overlay handles. Compatible ordered append/current-point changes use `update`; older corrections, backfills, reorder/truncation or incompatible shapes replace data. Prefix validation still scans data and retains private flat snapshots; this is not an O(1) streaming claim. Initial fit and explicit auto-fit toggles do not continually overwrite the user's chosen range. Changed level-price configurations may still recreate their handles.

## PR #849 source-review corrections

A subsequent source review found correctness gaps and updated this PR:

- Structural command/undo restoration preserves current runtime fields without retaining them in undo snapshots. Pin synchronization handles external unpin and no-op writes, publishes once per edit, and respects mutation locks.
- Document readiness includes owner identity. Saves and prepared runs wait for hydration, new templates clear prior cluster state, and Stop remains available while a saved run waits for its replacement session.
- Listener replacement aborts the old owner before staging new flags. Polling, recovery requests, delayed flag resets, stream controls and news callbacks reject obsolete sessions/deleted nodes. Clear Runtime terminates pending polling without recreating cleared state. Listener and socket publications mirror changed runtime fields to canonical nodes, then explicitly notify once; full configuration patches cannot accidentally trip execution locks.
- History refresh resets pagination authoritatively; bounded windows retain their cursor boundary. Selection refreshes cached terminal details, resumes after hidden intervals, rejects rows that left the filters, and coalesces repeated selection during a detail request.
- Shared loader ownership survives effect teardown/restart without reviving old requests. Supporting pages reset old scope state and surface query failures. Supabase realtime filters use the supported syntax; live snapshots are deduplicated, ordered and reconciled with full reads without mixing sessions.
- Hidden conditional options/previews no longer activate requests. Chart overlay shapes are scoped to their pane, multi-series updates preserve duplicate-label channels, and new panes inherit the current visible range. JSON paging clamps after data shrinks and retains explicit reference paths.

These corrections were reviewed in source only. No tests, type check, lint, build, browser exercise, profiling or remote runtime execution was performed. `git diff --check` checks whitespace only and does not establish runtime correctness.
